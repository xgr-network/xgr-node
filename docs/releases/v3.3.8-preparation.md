# XGR v3.3.8 — Direct-BLS completed quorum replication (release preparation)

Target branch: `XGR3.0`. Base release: immutable `v3.3.7`. Source change: PR #75.

## Scope
- Publish complete, previously validated 2/3 BLS quorum artifacts over bounded interchain gossip.
- Peers independently verify the signed canonical route, domain and contract identities, current destination BLS validator set and effective ISM, aggregate signature and signer bitmap, plus undelivered state, before persisting.
- Keep the two independent source RPC witness requirement and `safe` finality for all NEW local signatures. Never reduce BLS quorum or skip executor contract-side verification.
- Do not touch ordinary IBFT/PoS consensus, chain state transition, staking, custody, XITA wallet flow, or contracts.

## Release gate (must pass before immutable tag)
1. PR #75 code review and complete CI (unit, focused security regression, build).
2. Three-validator staging test: node A holds 1/2; nodes B/C each hold a valid complete attestation; synchronize node A using P2P. Verify same route/message/current set, valid aggregate, no newly signed votes and no repeated external source RPC requirement for importing an already completed attestation.
3. Negative cases: forged BLS aggregate, insufficient bitmap, stale setId, mismatched destination ISM/registry/route/message; ensure fail closed. Add inbound traffic amplification/load check.
4. Audit runtime error logs for unrelated IBFT `unable to build proposal` before production rollout.
5. Build `linux/amd64` binary with `-trimpath` and version metadata `v3.3.8`, emit `version.txt`, `commit.txt` and `sha256sums.txt`; recheck `sha256sum -c`.
6. Review precise `XGR3.0` 40-char release SHA and verify `v3.3.7` is its ancestor and `v3.3.8` does not already exist. Trigger an explicit guarded manual release workflow; never replace a published tag.
